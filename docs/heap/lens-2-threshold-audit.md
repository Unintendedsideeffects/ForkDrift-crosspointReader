## One consistent policy

### Proposed `HeapGuard` contract

**Label: inferred recommendation.** Set `kLowFloorBytes = 40 * 1024` (40,960) and `kCriticalFloorBytes = 24 * 1024` (24,576), provisionally. Healthy reader idle is measured at 36,348–40,428, so it belongs in **Low**—core reading allowed, luxuries deferred—not Critical; a successful render was measured at 24,656 during selection indexing, only 80 bytes above the proposed Critical line. `traces/03-open-book-degrade.log:35-54`; `traces/04-post-fix-page-turns.log:6-23`; `traces/04-post-fix-page-turns.log:43-65`; `lib/Memory/HeapGuard.h:27-38`

The exact minimum system-stability floor is **unknown** from these traces: the healthy run's minimum-free-ever was 12,956, but that is a historical low-water mark rather than the admission point of a known allocation. Therefore 24/40 KiB should be treated as the first device-validation candidate, not a proven physical limit. `traces/04-post-fix-page-turns.log:3-6`; `traces/04-post-fix-page-turns.log:43-43`

**Label: inferred recommendation.** Add a typed admission result to `HeapGuard.h/.cpp`, for example `Admission { Ok, InsufficientTotal, Fragmented } check(bytes, floorAfter)`, and named wrappers `checkCore(bytes)` (Critical floor) and `checkLuxury(bytes)` (Low floor). Keep per-operation byte estimates, but prohibit per-feature safety floors and total-only gates. This preserves the existing two-condition arithmetic while allowing callers to distinguish total pressure from fragmentation. `lib/Memory/HeapGuard.h:8-21`; `lib/Memory/HeapGuard.cpp:49-55`

**Label: inferred recommendation.** Essential paths must follow the fixed render contract: reclaim safe caches/services, remeasure once, attempt only nothrow allocations, and surface a typed memory result; they must not use a zero-byte floor as a terminal gate. Corruption recovery must run only on a typed corrupt-data result. `src/activities/reader/EpubReaderActivity.cpp:1798-1826`; `lib/Epub/Epub/Section.cpp:591-604`

## Bottom line
